# Verification Tasks

Source: https://chatgpt.com/space/page_0fd4224e704c81919586cc2a1b2404cc

Exported 2026-09-30. Historical planning record; current local audits and engineering evidence supersede obsolete statements about missing files or checks. The full original rocksalt application is not release-verified.

These tasks resolve the rocksalt companion’s scientific and implementation questions. They are pending work, not passing test results. Human expert review is optional and not required for release.

## Recover the evidence

- [ ] Recover the original and improved visualizer HTML, revised launch pack, and full audit.

- [ ] Record checksums and preserve baseline versions.

- [ ] Collect the exact anchor paper version, figure, caption, methods, supporting information, primary references, and available structure data.

- [ ] Record unavailable evidence and reconcile the original claim ledger.

## Resolve the model

- [ ] Identify oxygen coordination geometry and neighboring cation geometry separately.

- [ ] Define composition, lithiation state, site mapping, and spinel occupancy.

- [ ] Specify species, vacancies, hop rules, graph edges, boundaries, outputs, and units.

- [ ] Define composition normalization, finite cell rounding, order control, and seed handling.

- [ ] Decide which outputs are schematic, qualitative, or quantitatively supported.

- [ ] Label the animation a connectivity probe unless a physical trajectory model passes appropriate checks.

## Independent reference and fixture checks

- [ ] Construct hand-checkable local geometry examples.

- [ ] Construct disconnected, connected, and boundary spanning graph fixtures.

- [ ] Establish occupancy and species count fixtures independently of production code.

- [ ] Compare geometry and connectivity against a separate reference calculation when useful.

- [ ] Define expected results and tolerances before examining production outputs.

## Invariant and sampling checks

- [ ] Check species counts, rounding, graph consistency, and equivalent geometry under appropriate symmetry.

- [ ] Check limiting and boundary cases for the declared parameters.

- [ ] Check reproducibility for fixed seeds.

- [ ] Document finite size and multiple realization behavior before making statistical claims.

- [ ] Keep literature percolation conditions distinct from results for the teaching cell.

## Adversarial AI critique

- [ ] Challenge unsupported mechanisms, rates, thresholds, slider meanings, and geometry labels.

- [ ] Check every claim against its exact source conditions.

- [ ] Resolve findings or narrow release scope; retain the critique record.

- [ ] Do not treat agreement between AI systems as empirical validation.

## Browser and visual semantic checks

- [ ] Confirm rendered entities match model outputs.

- [ ] Check labels, legends, units, denominators, and probe wording.

- [ ] Check reset, camera presets, parameter controls, and seed behavior.

- [ ] Check keyboard operation, reduced motion, pausable animation, responsiveness, and text fallback.

- [ ] Verify that hidden atoms do not imply physical removal.

## Release record

- [ ] Save the exact code version, artifact checksum, representation type, checks, unresolved limits, and approved claims.

- [ ] Assign source-traced, model-checked, or release-verified only when their criteria are met.

- [ ] Publish within the documented scope after required checks pass.

Optional human review can be added later with its exact scope and version. It does not belong in the required checklist.
